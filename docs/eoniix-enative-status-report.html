eoniix KYC API Gaps

Critical

Sandbox and mock issuance

Dojah sandbox and Solana devnet/mock outputs mean the service is not yet production proof. Responses may look verified while still representing test credentials.

Critical

Fake DID fallback

The verify flow can generate a placeholder DID when an eNumber has no DID. That should be replaced by a hard failure or a real call into the issuer DID-linking path.

High

Startup/import blockers

The inspected tree references missing modules such as src/middleware/security.js and src/admin/swaggerInternal.js. Those imports can prevent the API from booting cleanly.

High

Test quality

Tests appear to hit the live public API and include a fallback live-looking API key. They need local hermetic tests, sandbox integration tests, and secret-free fixtures.

Medium

Scope enforcement gap

The repo has per-client API key auth primitives, but route-level scope requirements need to be consistently applied for partner actions.

Medium

Operational hygiene

The repo contains a Windows-invalid filename, tracked Supabase temp files, and a committed zip artifact. These make checkout, review, and CI less reliable.

Recommended Route

Priority Action Reason
P0 Make sandbox/devnet status explicit in API responses and docs. Prevents test credentials being mistaken for production credentials.
P0 Remove fake DID generation from KYC verification. Credential issuance must bind to a real subject DID or fail closed.
P1 Fix missing imports and Windows-invalid repository path. The codebase needs clean checkout and boot before deeper QA is meaningful.
P1 Replace live API tests with local route tests and sandbox integration tests. Tests should be deterministic, secret-free, and safe to run in CI.
P2 Move rate limits to a distributed store keyed by API key ID, not raw key text. Supports multi-instance deployment and avoids keeping plaintext key material in memory.
